Бинарный поиск: в *отсортированном* массиве мы можем заметно быстрее найти требуемый элемент, беря среднее значение и применяя к нему какой-то логический критерий (например больше или меньше), и на основе полученного результата сокращать рамки возможных чисел (так как массив отсортирован), пока мы не придем к нужному элементу. Грубо говоря, на основе среднего значения отсекаем ту или иную половину ($a_{(1, 2, \ldots )} < a_{\frac12 n}, \text{ }a_{\frac12 n}<k \to a_{(1, 2, \ldots ) }< k$). Сложность такого алгоритма или максимальное количество шагов $\log_2n$ (стр. 21)

^BinarySearch


```python
def binary_search(list, item):  
    low = 0  
    high = len(list)-1  
  
    while low <= high:  
        mid = (low + high)  
        guess = list[mid]  
        if guess == item:  
            return mid  
        if guess > item:  
            high = mid - 1  
        else:  
            low = mid + 1  
    return None
```

«Big-O» — показатель времени выполнения алгоритма или с какой скоростью время выполнения алгоритма с увеличением размера входных данных. Чаще всего обозначает операции в худшем случае или в среднем

^BigO

Чаще всего встречаются пять разновидностей (от быстрой к медленной):
- $O(\log n)$ {бинарный поиск}
- $O(n)$ {простой поиск}
- $O(n \log n)$ {эффективные алгоритмы сортировки}
- $O (n^2)$ {медленные алгоритмы сортировки}
- $O(n!)$ {очень медленные алгоритмы}
(стр. 35)

На самом деле по сути $O$-большое означает это:$$c\cdot n$$
Здесь $n$ — количество операций, а $c$ — константное время выполнения. Но как показала практика, в подавляющем большинстве случаев константа не играет никакой роли, потому что $n$ всегда даёт более ощутимый вклад (сравни $n$ и $n^2$). Это причина, почему константа всегда игнорируется.
Но есть все-таки частные случаи, как было с сортировкой слияния и быстрой сортировкой. 

(стр 94.)

На примере быстрой сортировки можно рассмотреть принцип действия «Big-O».
В среднем и лучшем случае (когда pivot случайный) стек имеет глубину $O(\log n)$. Каждый раз мы проходимся по массиву  $O(n)$. В таком случае алгоритм займет $O(n\log n)$. 

В худшем случае, когда массив уже отсортирован, это займет $O(n) \times O(n) = O(n^2)$

def find_smallest(arr):  
    ismallest = 0  
    for x in range(1, len(arr)):  
        if arr[x] < arr[ismallest]:  
            ismallest = x  
    return ismallest  
  
def selectionSort(arr):  
    new_arr = []  
    for x in range(len(arr)):  
        smallest = find_smallest(arr)  
        new_arr.append(arr.pop(smallest))  
    return new_arr

Алгоритм быстрой сортировки — это алгоритм, который описывается следующими шагами:
1. Выбрать опорный элемент в массиве
2. Разделить массив на два подмассива: элементы, меньшие или равные опорного, и элементы, большие опорного
3. Рекурсивно применить быструю сортировку к двум подмассивам


^QuickSort

(стр.88)


```python
def quicksort(array):  
    if len(array) < 2:  
        return array  
    else:  
        pivot = array[0]  
        less = [i for i in array[1:] if i <= pivot]  
        greater = [i for i in array[1:] if i > pivot]  
        return quicksort(less) + [pivot] + quicksort(greater)  
  
  
print(quicksort([9, 3, 5, 6, 9, 1]))
```

Хеш-таблицы в Python — это словари (dict)

Суть хеш-таблиц вот в чём: существует хеш-функция, которая получает строку (набор байтов) и возвращает какое-то число. Это число будет индексом в массиве.
Когда необходимо прочитать информацию, то снова необходимо передать в хеш-функцию строку и получить индекс, по которому надо обращаться к массиву.
В отличии от любого алгоритма поиска хеш-таблица (связка хеш-функции и массива) ищет по массиву со скоростью $O(1)$, исходя из определения.

^HashTable

Хеш-функция должна соответствовать определенным требованиям:
- Она должна быть последовательной. Если мы передали строку `s` и получили $a$, то при всех последующих передачах мы должны получать тоже $a$
- Если мы передаем строки  `s` и `z`, то вывод их функций не должны быть одинаковыми

(стр. 103)

Хэш-таблицы эффективны, когда:
- Надо моделировать отношения между объектами
- Надо решать задачу устранения дубликатов
- Надо сохранять кэш

При проектировании хеш-таблиц мы можем столкнуться с проблемой коллизий: разным элементам будет соответствовать одно значение. В таком случае нам придётся для одной ячейки создать связанный список и провести в нём поиск. 
Из этого следует:
- Выбор хеш-функции очень важен. В идеале она должна равномерно распределять ключи по всему хешу
- Если связанные списки становятся длинными, то работа с хэш-таблицей сильно замедляется
(стр. 119)

Эффективность хэш-функции описывается так:

|          | Хеш-таблица<br>(средний случай) | Хеш-таблица<br>(худший случай) | Массивы | Списки |
| -------- | :-----------------------------: | :----------------------------: | :-----: | :----: |
| Чтение   |             $O(1)$              |             $O(n)$             | $O(1)$  | $O(n)$ |
| Запись   |             $O(1)$              |             $O(n)$             | $O(n)$  | $O(1)$ |
| Удаление |             $O(1)$              |             $O(n)$             | $O(n)$  | $O(1)$ |
(стр. 121)

Для предотвращения коллизий необходимо:
- Иметь низкий коэффициент заполнения. Обычно при значение $0.7$ хеш-таблица расширяется в два раза, чтобы избежать коллизий. Он вычисляется как $\dfrac{\text{n элементов в таблице}}{\text{общее количество элементов}}$
- Иметь хорошую хеш-функцию (SHA)

Граф — это структура данных, которая моделирует связи между разными объектами и который состоит из рёбер и узлов. Соединенные рёбрами узлы называются соседними

^graph

(стр. 132)
![[Pasted image 20240710160852.png]]

Поиск в ширину по графу позволяет ответить на вопросы:
- Существует ли путь между узлами $A$ и $B$ 
- Как выглядит кратчайший путь между $A$ и $B$

(стр. 132)

Графы бывают:
- Направленные. Отношения действуют только в определенную сторону
- Ненаправленный. Отношения всегда эквивалентны для обоих
- Взвешенные 
- Незвешенные 
- Циклические
- Ациклические (ненаправленные тоже считается)

(стр. 140)

Мы можем говорить о связях разных уровней: если за узлом следует второй, то они будут находится на разных уровнях. В некоторых задачах предпочтительно рассматривать сначала именно родительский узел.

Граф может быть реализован с помощью хеш-таблицы.

Время выполнения: $O(V+E)$, где $V$ — количество вершин, а $E$ — количество рёбер
 
Допустим у нас есть задача пройтись по всем людям, начиная с пользователя, в хеш-таблице и найти ближайшего продавца манго.
Код может выглядеть так:

```python
from collections import deque

graph = {}
graph["Jim"] = ["Cler", "Alice", "Bob"]
graph["Cler"] = ["Tom", "Johan"]
graph["Alice"] = ["Peggi"]
graph["Bob"] = ["Peggi", "Willy"]
graph["Tom"] = []
graph["Johan"] = []
graph["Peggi"] = []
graph["Willy"] = []

def person_is_celler(person):
    if person == "Johan" or person == "Alice":
        return True
    else:
        return False

def search(name):
    search_queue = deque()
    search_queue += graph[name]
    searched = []
    while search_queue:
        person = search_queue.popleft()
        if not person in searched:
            if person_is_celler(person):
                print(person, "is mango seller!")
                return True
            else:
                search_queue += graph[person]
                searched.append(person)
    return False

print(search("Cler"))
```

Алгоритм Дейкстеры — это алгоритм, который позволяет производить поиск кратчайшего пути во взвешенном графе

^DijkstrasAlgorithm

Алгоритм состоит из четырёх шагов"
1. Найти узел с наименьшей стоимостью
2. Проверить существует ли более дешевый путь к соседям узла, и если существует, обновить их стоимость 
3. Повторять, пока это не будет сделано для всех узлов графа
4. Вычислить итоговый путь

(стр. 157)

Некоторые ограничения:
- Граф должен быть ациклическим
- Граф должен быть ненаправленным 
- Граф  не должен иметь отрицательных весов

Жадные алгоритмы — это алгоритмы, которые основаны на поиске локально-оптимального решения, приводящее зачастую к поиску глобально-оптимального решения

^JealousAlgorithm

Однако, они не всегда  дают точный результат, но всегда дают результат близкий к оптимуму.

Например, нам надо максимально эффективно покрыть территорию радиостанциями. Для этого мы можем выбрать наилучший вариант (покрывает большинство станций), потом следующий наилучший вариант (покрывает большинство оставшихся) и так далее. Вот код:

```python
states_needed = {'mt', 'wa', 'or', 'id', 'nv', 'ut', 'ca', 'az'}  
  
stations = {}  
stations['kone'] = {'id', 'nv', 'ut'}  
stations['ktwo'] = {'wa', 'id', 'mt'}  
stations['kthree'] = {'or', 'nv', 'ca'}  
stations['kfour'] = {'nv', 'ut'}  
stations['kfive'] = {'ca', 'az'}  
  
final_stations = set()  
  
while states_needed:  
    best_station = None  
    states_covered = set()  
    for station, states_for_stantion in stations.items():  
        covered = states_needed & states_for_stantion  
        if len(covered) > len(states_covered):  
            best_station = station  
            states_covered = covered  
    states_needed -= states_covered  
    final_stations.add(best_station)  
  
print(final_stations)
```

Жадные алгоритмы могут хорошо себя показать в задачах на заполнения множества и задаче о коммивояже. Это трудные NP-полные задачи, поиск идеального решения которых занимает слишком много времени. Поэтому выгоднее решать их жадным алгоритмом и получать приближенное значение за оптимальное время.

Признаки NP-полных задач, которые не стоит решать через идеальное решение:
- Алгоритм быстро работает при малом количестве, но сильно замедляется при увеличении данных. $O(n!)$
- Формулировка «все комбинации $X$» может указывать на такую задачу
- Приходится вычислять все возможные варианты $X$, а задача не разбивается на подзадачи
- Если в задаче фигурирует последовательность или множество и нет простого решения на первый взгляд
- Если задачу можно переформулировать в задачу о радиостанциях или коммивояже

-----------
Динамическое программирование.

^dynamicProgramming

Рассмотрим задачу: мы вор и у нас есть рюкзак, который переносит вещи массой до 4 фунтов. У нас есть три позиции в магазине:
- Гитара (1 фунт и 1500$)
- Ноутбук (2 фунта и 2000$)
- Магнитофон (4 фунта и 3000$)

Теперь составим таблицу, где столбцы будут представлять размер рюкзака

|            | 1     | 2     | 3     | 4     |       |
| ---------- | ----- | ----- | ----- | ----- | ----- |
| Гитара     | 1500$ | 1500$ | 1500$ | 1500$ | 1500$ |
| Магнитофон | 1500$ | 1500$ | 1500$ | 3000$ |       |
| Ноутбук    | 1500$ | 1500$ | 2000$ | 3500$ |       |

Мы заполняем эту таблицу по логике:
1. Мы берём либо предыдущий в строке максимум
2. Мы прибавляем к стоимости элемента стоимость оставшегося места

*Ответ не всегда в конце*

У алгоритма есть ограничения:
- Нельзя взять часть предмета
- Элементы должны быть автономны (выбор одного не повлияет на другой)
- Порядок не влияет на результат

Динамическое программирование необходимо применять при решении оптимизационных задач в ограниченных условиях. Некоторые советы:
- При решении таких задач должна строится таблица
- Значение ячеек обычно характеризуют оптимизируемой характеристике
- Каждая ячейка представляет подзадачу

Суть алгоритма $k$ ближайших соседей достаточно проста:
если мы по каким-то признакам разделяем объекты на классы, то по этим признакам можно определить класс другого объекта, найди ближайших к нему соседей (классификация). Или же по ближайшим соседям можно вычислить примерное значение (регрессия)

^NearestKAlghoritm

![[Pasted image 20240726134043.png]]Чтобы  определить ближайших соседей, достаточно воспользоваться теоремой Пифагора, которую легко распространить на любое измерение, что делает количество параметров бесконечным: $$\sqrt{(a_1-a_2)^2+(b_1-b_2)^2+\ldots+(\gamma_1-\gamma_2)^2}$$
(Другие алгоритмы для $k$ ближайших приведены в статье)

Всегда важно, чтобы признаки:
- Были связаны с темой классификации
- Полно отражали суть объекта

На основе алгоритма $k$ ближайших соседей решаются задачи:
- Классификации машинным интеллектом (OCR или оптическое распознавание текста)
- Построение спам-фильтра (наивный классификатор Байеса)
- Прогнозы

Бинарные древа поиска. Суть в том, что при бинарном поиске операция удаление или вставки в массиве выполняется со скорость $O(N)$. Скорость не очень хорошая, поэтому была предложена концепция бинарного древа. 

Бинарное древо поиска характеризуется тем, что от исходного узла отходят две ветви, одна из которых содержит значения большие узла, а другая — меньшие

Пример для последовательности чисел: 71, 88, 6, 43, 32, 86, 60, 33, 69, 12, 100

![[Pasted image 20240726153838.png]]

Вставка, удаление и поиск в целом напоминают бинарный.

|          |   Массив    | Бинарное дерево <br>поиска |
| -------- | :---------: | :------------------------: |
| Поиск    | $O(\log n)$ |        $O(\log n)$         |
| Вставка  |   $O(n)$    |        $O(\log n)$         |
| Удаление |   $O(n)$    |        $O(\log n)$         |

Недостатки бинарного дерева поиска:
- Отсутствие произвольного поиска
- Для эффективной работы дерево должно быть сбалансировано и не должно быть перекосов в одну сторону

Инвертированный индекс — это хэш-таблица, которая содержит в себе термин, или слово в качестве ключа и ссылка на документы/источники, где встречается этот термин

------------
Параллельные алгоритмы позволяют повысить быстродействие программы, но, увы, надо учитывать несколько моментов:
- Существуют затраты ресурсов на управление параллелизмом (два ядра сделали работу за время $n$? А теперь надо объединить их и потратить ресурсы)
- Распределять нагрузку надо правильно, чтобы ядра не простаивали

------------
Распределенные алгоритмы — алгоритмы, которые работают на нескольких машинах

--------
Фильтры Блума — это вероятностная структура данных. Он может дать ответ, содержится ли элемент в наборе данных, при этом не занимая место, как хеш-таблица. Но:
- Он подвергается ложно-положительным срабатываниям 
- Ложно-отрицательные срабатывания исключены

-----
HyperLogLog — тоже вероятностный алгоритм, который приблизительно оценивает мощность множества

----
Алгоритмы SHA генерируют из строк хеш-коды этой строки.
Их можно использовать при сравнении больших файлов и проверке паролей (функции одностороннии и восстановить из хеша строку нельзя).

Также они могут быть:
- Локально-нечувствительными (при изменении одного символа меняется все строка)
- Локально-чувствительными
